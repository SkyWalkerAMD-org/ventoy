# Rocky Linux 9 客户端验收

本页记录客户端实装；管理服务器的部署步骤见 [Rocky 9 服务端](rocky9.md)。当前范围为 x86_64、UEFI、Intel X710 网启和一块按序列号指定的 SATA 磁盘，另一块磁盘保留。其他固件、硬件和并发安装尚未验收。

## Rocky 9.2

2026-10-16，iVentoy 1.0.45 Pro 与管理端 alpha.9 的任务 `e9885756e98fe74fe3d32f38` 完成自动安装：

- DVD 内部版本、架构和内嵌介质校验通过。
- `01:36:43Z` 自动领取安装授权，`01:41:04Z` 硬盘启动后回报 `installed`。
- 自动分区、软件包安装、重启和 UEFI 硬盘启动通过；控制台密码登录、SSH 公钥登录及 sudo 通过。
- 根分区和 EFI 分区都属于指定序列号磁盘；保留盘的分区表、文件系统与 LVM 签名与基线一致。
- 首次启动脚本成功完成后删除，服务禁用；旧任务凭据重放返回 HTTP 401。

这次首次启动发现 `NetworkManager-wait-online` 等待 60 秒后失败。安装器把其他网口自动生成的 DHCP 连接带入系统，其中 BMC USB 网卡没有收到租约。NetworkManager 的在线等待服务会等待启动时的连接处理结束，参见[官方说明](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/NetworkManager-wait-online.service.html)。

alpha.10 在 Rocky 9 的 `%post` 中离线处理已安装系统的 keyfile：保留指定 MAC 连接，只把其他以太网口中优先级为 -999 的自动生成连接设为手动启用；不改自定义连接、非以太网连接或安装环境正在使用的网络。应用同一修复后，第二次正常硬盘启动通过，无失败服务，用户空间启动由 66.844 秒降为 8.488 秒，保留盘仍与基线一致。

### alpha.10 完整新装回归

同日，新任务 `bba89ab191b5bc79c03e62ef` 在 iVentoy 1.0.45 Pro 下完成全新无人值守安装，安装后没有手工修改网络配置：

| 检查 | 结果 |
| --- | --- |
| 自动安装 | `02:39:31Z` 领取授权，自动分区、安装 377 个软件包并重启；`02:42:57Z` 首次硬盘启动回报 `installed` |
| 系统与登录 | Rocky Linux 9.2，内核 `5.14.0-284.11.1.el9_2.x86_64`；控制台密码、SSH 公钥与 sudo 验证通过 |
| 网络修复 | `%post` 将 3 个其他网口的安装器自动连接设为手动启用；指定 MAC 的连接正常，在线等待服务成功 |
| 首次启动 | 自动从目标盘启动；用户空间 12.804 秒，无失败服务 |
| 再次重启 | 移除已完成任务的单机网启规则，未设置 BootNext；再次正常从硬盘启动，boot ID 改变，用户空间 8.470 秒，无失败服务 |
| 磁盘保护 | 两次硬盘启动均按序列号核对根分区、EFI 分区归属；保留盘的分区表和文件系统 / LVM 签名与基线一致 |
| 完成清理 | 回报服务成功后禁用，临时凭据脚本已删除；旧授权重放返回 HTTP 401 |
| 基础系统 | DHCP、到控制器的路由、sshd 正常，SELinux Enforcing，root 密码锁定 |

两次启动分别保存 29 项验收信息。正常重启时设备名再次交换，序列号检查仍正确识别目标盘与保留盘。保留盘检查不包含整盘逐字节数据校验。

安装前在获授权的 live 环境中单独处理了目标盘旧 LVM，并核对保留盘不变；这一步仍不是安装模板的自动拆除功能。上述结果完成了 alpha.10 网络修复的全新安装与第二次重启验收。

## 其他 Rocky 9 镜像

9.6、9.7、9.8 的 ISO 内部版本、x86_64 架构、内嵌介质校验和 SHA-256 记录已完成；每个版本仍需独立实装。不能用 9.2 的成功结果替代其他小版本。

每轮保存安装事件、控制台登录证据、SSH 身份核对、磁盘归属、保留盘基线对比及重启结果。设备名可能在启动后交换，验收始终按序列号识别磁盘，不依赖固定的 `sda` / `sdb`。
